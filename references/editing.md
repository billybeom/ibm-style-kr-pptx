# 기존 IBM 프레젠테이션 편집

## IBM 특화 유의사항

편집 전, 프레젠테이션이 IBM 스타일인지 확인하십시오:
- 캔버스는 반드시 **26.67" × 15.00"** (표준 10" × 5.625" 아님)
- 폰트는 반드시 **IBM Plex Sans KR** 패밀리 (Arial 또는 다른 폰트 아님)
- 첫 번째 슬라이드는 반드시 **커버** (페이지 번호 없음)
- 마지막 슬라이드는 반드시 **엔딩** (페이지 번호 없음)
- 그 외 모든 슬라이드에는 **x=25.75" y=14.16"**에 페이지 번호 있어야 함
- 모든 본문/레이블 텍스트는 **최소 28pt** (표 내부는 20pt만 허용)

프레젠테이션이 IBM 기준을 위반하는 경우, 편집하면서 함께 수정하십시오.

## 템플릿 기반 워크플로우

기존 프레젠테이션을 템플릿으로 사용할 때:

1. **복사 및 분석**:
   ```bash
   cp /path/to/user-provided.pptx template.pptx
   python -m markitdown template.pptx > template.md
   ```
   `template.md`를 검토하여 플레이스홀더 텍스트와 슬라이드 구조를 확인하십시오.

2. **슬라이드 매핑 계획 수립**: 각 콘텐츠 섹션에 적합한 템플릿 슬라이드를 선택하십시오.

   **다양한 IBM 레이아웃 사용** — 단조로운 프레젠테이션은 흔한 실패 패턴입니다. 기본 제목 + 불릿 슬라이드에만 머물지 마십시오. IBM 템플릿 카테고리를 적극 활용하십시오:
   - Big Trending (굵은 수치, 강렬한 주장)
   - 다단 레이아웃 (2단, 3단, 4단)
   - 행 기반 레이아웃 (2행, 3행 수평 콜아웃)
   - 그리드 레이아웃 (2×2, 2×3, 3×3 박스)
   - 이미지 반쪽 + 텍스트 조합
   - 주요 섹션 사이에 섹션 구분자
   - 필요한 곳에 표 또는 프로젝트 플랜

   **주의**: 연속된 슬라이드에 같은 카테고리 반복 금지.

   콘텐츠 유형을 IBM 템플릿 카테고리에 맞추십시오 (예: 핵심 수치 → Big Trending, 비교 → 2단, 팀 역할 → 3단, 로드맵 → 프로젝트 플랜).

3. **압축 해제**: Python의 `zipfile` 모듈을 사용해 PPTX를 편집 가능한 XML 트리로 추출. 가독성을 위해 XML을 보기 좋게 포맷.

4. **프레젠테이션 빌드** (서브에이전트 없이 직접 수행):
   - 불필요한 슬라이드 삭제 (`<p:sldIdLst>`에서 제거)
   - 재사용할 슬라이드 복제 (슬라이드 XML, 관계 파일 복사, `Content_Types.xml` 및 `presentation.xml` 업데이트)
   - `<p:sldIdLst>`에서 슬라이드 순서 변경
   - **5단계 전에 모든 구조적 변경 완료**

5. **콘텐츠 편집**: 각 `slide{N}.xml`의 텍스트 수정.
   **가능하면 여기서 서브에이전트 사용** — 슬라이드는 별도 XML 파일이므로 서브에이전트가 병렬로 편집 가능.

6. **정리**: 고아 파일 제거 — `<p:sldIdLst>`에 없는 슬라이드, 참조되지 않는 미디어, 고아 관계 파일.

7. **재압축**: XML 트리를 PPTX 파일로 다시 압축. 유효성 검사, 수리, XML 압축, 스마트 따옴표 재인코딩.

   항상 `/tmp/`에 먼저 쓴 다음 최종 경로로 복사하십시오. Python의 `zipfile` 모듈은 내부적으로 `seek`를 사용하며, 이는 일부 볼륨 마운트(예: Docker 바인드 마운트)에서 실패할 수 있습니다. 로컬 임시 경로에 쓰면 이 문제를 피할 수 있습니다.

## 출력 구조

사용자 제공 파일을 현재 디렉토리의 `template.pptx`로 복사하십시오. 원본을 보존하고 모든 후속 작업에 예측 가능한 이름을 제공합니다.

```bash
cp /path/to/user-provided.pptx template.pptx
```

```text
./
├── template.pptx               # 사용자 제공 파일 복사본 (절대 수정 금지)
├── template.md                 # markitdown 추출 결과
├── unpacked/                   # 편집 가능한 XML 트리
└── edited.pptx                 # 최종 재압축 덱
```

최소 납품 결과물: `edited.pptx`.

## 슬라이드 조작

슬라이드 순서는 `ppt/presentation.xml` → `<p:sldIdLst>`에 있습니다.

**순서 변경**: `<p:sldId>` 요소의 순서를 바꾸십시오.

**삭제**: `<p:sldId>`를 제거한 후 고아 파일을 정리하십시오.

**추가**: 소스 슬라이드의 XML 파일, `.rels` 파일을 복사하고 `Content_Types.xml`과 `presentation.xml`을 업데이트하십시오. 모든 참조를 업데이트하지 않고 슬라이드 파일을 수동으로 복사하지 마십시오 — 이로 인해 노트 참조가 깨지고 관계 ID가 누락될 수 있습니다.

## 콘텐츠 편집

**서브에이전트**: 4단계 완료 후 사용 가능하면 여기서 활용하십시오. 각 슬라이드는 별도 XML 파일이므로 서브에이전트가 병렬로 편집 가능합니다. 서브에이전트 프롬프트에 포함할 내용:
- 편집할 슬라이드 파일 경로
- **"모든 변경에 Edit 도구 사용"**
- 아래 형식 규칙 및 일반적인 함정

각 슬라이드에 대해:
1. 슬라이드의 XML 읽기
2. 모든 플레이스홀더 콘텐츠 식별 — 텍스트, 이미지, 차트, 아이콘, 캡션
3. 각 플레이스홀더를 최종 콘텐츠로 교체

**sed나 Python 스크립트가 아닌 Edit 도구를 사용하십시오.** Edit 도구는 무엇을 어디서 교체할지 구체적으로 지정하도록 강제하여 더 높은 신뢰성을 제공합니다.

## 형식 규칙

- **모든 헤더, 소제목, 인라인 레이블에 볼드 적용**: `<a:rPr>`에 `b="1"` 사용. 다음을 포함:
  - 슬라이드 제목
  - 슬라이드 내 섹션 헤더
  - 줄 시작의 인라인 레이블 (예: "상태:", "설명:")
- **유니코드 불릿 사용 금지**: `<a:buChar>` 또는 `<a:buAutoNum>`으로 적절한 목록 형식 사용
- **불릿 일관성**: 레이아웃에서 불릿을 상속하십시오. `<a:buChar>` 또는 `<a:buNone>`만 지정하십시오.

## 일반적인 함정 — 템플릿 편집

### 템플릿 적응

소스 콘텐츠의 항목 수가 템플릿보다 적을 때:
- **초과 요소를 완전히 제거** (이미지, 도형, 텍스트 박스) — 텍스트만 지우지 말 것
- 텍스트 콘텐츠를 지운 후 고아 시각 요소 확인
- 항목 수 불일치를 잡기 위해 `markitdown`으로 콘텐츠 QA 실행

다른 길이의 콘텐츠로 텍스트를 교체할 때:
- **짧은 교체**: 보통 안전
- **긴 교체**: 오버플로우 또는 예기치 않은 줄 바꿈 발생 가능
- 텍스트 변경 후 `markitdown`으로 확인
- 템플릿의 디자인 제약에 맞게 콘텐츠를 잘라내거나 분할하는 것을 고려

**템플릿 슬롯 ≠ 소스 항목 수**: 템플릿에 팀원 4명이 있지만 소스에 사용자 3명이 있다면, 4번째 구성원의 전체 그룹(이미지 + 텍스트 박스)을 삭제하십시오 — 텍스트만 지우지 마십시오.

### 다중 항목 콘텐츠

소스에 여러 항목(번호 매긴 목록, 여러 섹션)이 있는 경우, 각각에 대해 별도의 `<a:p>` 요소를 생성하십시오 — **하나의 문자열로 연결하지 마십시오**.

**잘못된 예** — 하나의 단락에 모든 항목:
```xml
<a:p>
  <a:r><a:rPr .../><a:t>1단계: 첫 번째 작업. 2단계: 두 번째 작업.</a:t></a:r>
</a:p>
```

**올바른 예** — 볼드 헤더가 있는 별도 단락:
```xml
<a:p>
  <a:pPr algn="l"><a:lnSpc><a:spcPts val="3919"/></a:lnSpc></a:pPr>
  <a:r><a:rPr lang="ko-KR" sz="2799" b="1" .../><a:t>1단계</a:t></a:r>
</a:p>
<a:p>
  <a:pPr algn="l"><a:lnSpc><a:spcPts val="3919"/></a:lnSpc></a:pPr>
  <a:r><a:rPr lang="ko-KR" sz="2799" .../><a:t>첫 번째 작업을 수행합니다.</a:t></a:r>
</a:p>
<a:p>
  <a:pPr algn="l"><a:lnSpc><a:spcPts val="3919"/></a:lnSpc></a:pPr>
  <a:r><a:rPr lang="ko-KR" sz="2799" b="1" .../><a:t>2단계</a:t></a:r>
</a:p>
<!-- 패턴 계속 -->
```

행간을 유지하기 위해 원본 단락에서 `<a:pPr>`을 복사하십시오. 헤더에는 `b="1"` 사용.

### 스마트 따옴표

Edit 도구는 스마트 따옴표를 ASCII로 변환합니다. **따옴표가 있는 새 텍스트를 추가할 때 XML 엔티티를 사용하십시오:**

```xml
<a:t>&#x201C;계약&#x201D;</a:t>
```

| 문자 | 이름 | 유니코드 | XML 엔티티 |
|------|------|---------|------------|
| " | 왼쪽 큰따옴표 | U+201C | `&#x201C;` |
| " | 오른쪽 큰따옴표 | U+201D | `&#x201D;` |
| ' | 왼쪽 작은따옴표 | U+2018 | `&#x2018;` |
| ' | 오른쪽 작은따옴표 | U+2019 | `&#x2019;` |

### 기타

- **공백**: 앞뒤 공백이 있는 `<a:t>`에는 `xml:space="preserve"` 사용
- **XML 파싱**: `xml.etree.ElementTree` 아닌 `defusedxml.minidom` 사용 (네임스페이스 손상 방지)
